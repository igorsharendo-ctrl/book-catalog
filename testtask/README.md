# Каталог книг

Веб-приложение по тестовому заданию: каталог книг с авторами, подпиской гостей на SMS-уведомления и отчётом «ТОП 10 авторов».

Стек: **Yii2 Basic**, PHP 8.1, MySQL 8.0, Bootstrap 5. Точка входа — каталог `web/`.

## Возможности

| Роль | Что доступно |
| --- | --- |
| Гость | Просмотр книг и авторов, отчёт ТОП-10, подписка на SMS о новых книгах выбранного автора |
| Авторизованный пользователь | Всё то же плюс добавление, редактирование и удаление книг и авторов |

Регистрации нет: учётная запись создаётся миграцией. Автор книги — отдельная сущность, это не пользователь системы. Отписаться от SMS нельзя (в ТЗ не требовалось).

**Книга:** название, год выпуска, описание, ISBN, обложка. У книги может быть несколько авторов.

**Автор:** ФИО. У автора может быть несколько книг.

**Отчёт:** ТОП 10 авторов по количеству книг за выбранный год. Страница доступна всем.

**SMS:** при создании новой книги гости, подписанные на её авторов, получают сообщение через [SMSPilot](https://smspilot.ru/). Подключён ключ-эмулятор: шлюз принимает запрос, реальной отправки оператору нет.

## Требования

- PHP 8.1 (расширения: `pdo_mysql`, `mbstring`, `intl`, `gd` или `fileinfo`)
- MySQL 8.0
- Composer
- Веб-сервер с document root на `web/` (OpenServer / OSPanel, nginx, Apache)

## Установка

1. Скопируйте проект и установите зависимости:

```bash
composer install
```

2. Создайте базу данных MySQL, например `testtask`, кодировка `utf8mb4`.

3. Задайте переменные окружения для PHP CLI и веб-сервера:

- `DB_DSN` (по умолчанию `mysql:host=127.0.0.1;dbname=testtask`);
- `DB_USERNAME` (по умолчанию `root`) и `DB_PASSWORD`;
- `COOKIE_VALIDATION_KEY`: отдельный случайный секрет длиной не менее 32 символов;
- `DEMO_USER_PASSWORD`: выбранный вами пароль демо-пользователя, не менее 12 символов.

Случайный секрет можно сгенерировать командой `php -r "echo bin2hex(random_bytes(32)), PHP_EOL;"`. Сохраните его в окружении сервера. Приложение не загружает `.env` автоматически. Не добавляйте локальные секреты в Git. Без ключа cookie веб-приложение откажется запускаться. Для тестов задайте `DEMO_USER_PASSWORD`, совпадающий с использованным при заполнении тестовой БД.

4. Примените миграции (схемы и демо-данные):

```bash
php yii migrate --interactive=0
```

На Windows то же самое: `yii.bat migrate --interactive=0`.

5. Каталоги `runtime/`, `web/assets/` и `web/uploads/` должны быть доступны веб-серверу на запись.

6. Document root виртуального хоста — каталог `web/`. Для OpenServer / nginx уже есть `web/Nginx_1.21_vhost.conf` (хост `testtask.local`, ЧПУ через `try_files`). После добавления домена перезапустите сервер.

7. Откройте сайт в браузере, например http://testtask.local/

## Демо-доступ

| | |
| --- | --- |
| Логин | `user` |
| Пароль | Значение `DEMO_USER_PASSWORD`, заданное перед миграцией |

В базе уже есть авторы, книги за несколько лет ; подписки создаются вручную. Для отчёта ТОП-10 удобно выбрать год **2024**.

## SMS-уведомления

Компонент `app\components\SmsPilot` вызывает API-1: `https://smspilot.ru/api.php`.

- ключ-эмулятор задан в `config/params.php` (`smsPilotApiKey`);
- параметр `test=1` — без передачи SMS оператору;
- уведомление уходит **только при создании** книги, не при редактировании;
- ответы шлюза пишутся в `runtime/logs/sms.log`.

Чтобы проверить цепочку: выйдите из учётки, подпишитесь гостем на автора, войдите как `user` и добавьте книгу с этим автором.

## Права доступа

RBAC (`yii\rbac\PhpManager`), файлы в `rbac/`. Роль `user` даёт право `manageCatalog` (CRUD книг и авторов). Гость (`?`) видит каталог, отчёт и может подписаться.

Пересоздать роли:

```bash
php yii rbac/init
```

## Структура

```
commands/          консольные команды (RBAC)
components/        клиент SMSPilot
config/            web, console, БД, параметры
controllers/       книги, авторы, подписки, отчёт, вход
migrations/        схема и демо-данные (дампа нет)
models/            сущности и формы
rbac/              роли и назначения
views/             шаблоны
web/               публичный корень, обложки в web/uploads/covers
```

## После очистки истории

Ранее записанные в Git секреты следует считать раскрытыми и заменить в используемых окружениях. Переписанная история не удаляет чужие клоны и кэш GitHub. Старые локальные клоны следует заменить свежими, чтобы не вернуть прежние коммиты при отправке.
